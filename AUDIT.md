# SocioSquad Audit Report

**Stack (verified):** Vite + React 18 + React Router v6 + TypeScript + Tailwind + shadcn/ui + Supabase (client-side, anon key) + TanStack Query + Vitest. It is **not** Next.js: there are no API routes, middleware or server actions, so RLS is the only security boundary. There is **no Admin role, page or table**; the `app_role` enum has only `volunteer` and `organization`. Admin is a Phase 4 feature.

## Top priorities
1. **DB-1 / AUTH-1 (Critical):** any user can self-assign roles, insert themselves as squad `leader`, and read all invite codes.
2. **DB-2/3/4 (High):** users can write their own `user_stats` (XP/hours), set `organizations.verified`, and insert a pre-attended registration.
3. **CFG-1/2 (High):** clean install/Vercel build fails (`i18next*` undeclared; `lovable-tagger` imported but removed from package.json).
4. **AUTH-3 (High):** OAuth redirects to `/auth/callback`, which has no route.
5. **PGB-1/2 (High):** XSS via unescaped `document.write` in the certificate and resume generators.
6. **DATA-1/2/55:** no QueryClient defaults, no timeout, no paused-project handling, no error boundary.
7. **Fake data shown as real** (Leaderboard, Dashboard charts, AI recommendations, Community panels, marketing stats).

SQL fixes are proposals only (see the DB section). They are not executed and need approval.

-- Helpers
CREATE OR REPLACE FUNCTION public.is_squad_member(p_user uuid, p_squad uuid)
RETURNS boolean LANGUAGE sql STABLE SECURITY DEFINER SET search_path=public AS
$$ SELECT EXISTS (SELECT 1 FROM squad_members WHERE user_id=p_user AND squad_id=p_squad) $$;

-- A: squads / members
DROP POLICY "Authenticated users can join squads" ON public.squad_members;
CREATE POLICY "Join as member only" ON public.squad_members FOR INSERT TO authenticated
  WITH CHECK (auth.uid()=user_id AND role='member');
-- leader row created by trigger when a squad is created
CREATE OR REPLACE FUNCTION public.add_squad_creator() RETURNS trigger LANGUAGE plpgsql SECURITY DEFINER SET search_path=public AS
$$ BEGIN INSERT INTO squad_members(squad_id,user_id,role) VALUES (NEW.id,NEW.created_by,'leader'); RETURN NEW; END $$;
CREATE TRIGGER trg_add_squad_creator AFTER INSERT ON public.squads FOR EACH ROW EXECUTE FUNCTION public.add_squad_creator();
-- (then remove client insert of leader row in useSquads.ts:109)
CREATE OR REPLACE FUNCTION public.join_squad_by_code(p_code text) RETURNS uuid
LANGUAGE plpgsql SECURITY DEFINER SET search_path=public AS $$
DECLARE s uuid; BEGIN
  SELECT id INTO s FROM squads WHERE invite_code=lower(trim(p_code));
  IF s IS NULL THEN RAISE EXCEPTION 'invalid code'; END IF;
  INSERT INTO squad_members(squad_id,user_id,role) VALUES (s,auth.uid(),'member') ON CONFLICT DO NOTHING;
  RETURN s; END $$;
REVOKE ALL ON FUNCTION public.join_squad_by_code(text) FROM PUBLIC, anon;
GRANT EXECUTE ON FUNCTION public.join_squad_by_code(text) TO authenticated;
-- scope reads (squads list page needs names only; invite_code readable by members only -> consider a view)
DROP POLICY "Anyone can view squads" ON public.squads;
CREATE POLICY "Members view squads" ON public.squads FOR SELECT TO authenticated
  USING (created_by=auth.uid() OR public.is_squad_member(auth.uid(), id));
DROP POLICY "Anyone can view squad members" ON public.squad_members;
CREATE POLICY "Members view members" ON public.squad_members FOR SELECT TO authenticated
  USING (public.is_squad_member(auth.uid(), squad_id));
DROP POLICY "Members can view challenges" ON public.squad_challenges;
CREATE POLICY "Members view challenges" ON public.squad_challenges FOR SELECT TO authenticated
  USING (public.is_squad_member(auth.uid(), squad_id));
DROP POLICY "Members can create challenges" ON public.squad_challenges;
CREATE POLICY "Leaders create challenges" ON public.squad_challenges FOR INSERT TO authenticated
